# 엔진 회귀 기록: 2026-11-25 강의 덱 v2

새 엔진(show-me engine 0.1.0)이 첫 사례의 덱을 같은 모습으로 다시 만드는지 확인한 기록이다. 원본은 읽기 전용으로 두었고, 촬영본과 차이 그림은 고객 앱 화면을 포함하므로 저장소에 넣지 않았다. 수치와 방법만 적는다.

## 대상

- 원본: `video-creator2/projects/2026-11-25-how-i-use-agents-v2/slides/index.html`(15장). `tools/build_v2.py`를 scratchpad로 출력을 돌려 다시 빌드한 결과와 바이트 단위로 같음을 먼저 확인했다. 그래서 `tools/`의 원본 조각을 이식의 출발점으로 썼다.
- 이식본: `.work/regress-v2/port_v2.py`가 원본 조각에서 기계적으로 만든다.
  - `index.html`: v2 슬라이드 본문을 글자 그대로 옮기고, 상단 바·확대 보기·전체 보기 마크업은 엔진이 만들게 뺐다. `SEC` 상수는 설정 JSON으로 옮겼다(회사 240초, 일상 840초, 강의 1200초).
  - `deck.css`: v1 CSS에서 엔진이 소유하는 규칙 78줄을 빼고 129줄과 v2 추가 CSS를 남겼다. 엔진 토큰(`--accent` 등)을 v2 색으로 지정했다.
  - `scenes.js`: v2 장면 4개(24시간 순환도, 밤사이 다섯 갈래, 앱 화면 갤러리, 간격 반복 띠)를 손으로 옮겼다. 바뀐 것은 `$` → `ShowMe.$`, `openLB` → `ShowMe.lightbox`, `window.__go(n-1)` → `ShowMe.go(n)`, 띠 애니메이션을 `enter` 훅으로 건 것뿐이다.
  - 엔진 파일은 수정 없이 복사했다.

## 방법

`.work/regress-v2/run.sh <출력 폴더>`가 원본을 두 번, 이식본을 한 번 찍고 비교한다.

- 촬영: `shoot.mjs`, 1920×1080, 장마다 `#N`으로 열고 새로 고침 뒤 1.3초(10장은 4.6초) 기다림. 끝나지 않는 애니메이션은 0초, 끝나는 애니메이션은 끝 상태로 고정.
- 상호작용 6장: v2 `shoot.cjs`와 같은 동작(9장 3번 장면, 11장 확대, 6장 확대 보기, 8장 2번 탭, 5장 원문 펼치기, 전체 보기).
- 비교: `compare_shots.py`, 채널 차이 8 이하는 같은 픽셀.

원본끼리 비교한 차이를 흔들림의 기준으로 삼았다. 이식본의 차이가 그 범위 안이면 같은 덱으로 본다.

- 6장의 차이는 모두 앱 화면 썸네일 그림 안쪽이었다(차이 그림 확인). 배치·글자·색은 같다. 원본도 실행마다 같은 영역이 달라진다.
- 엔진의 클래스 접두사와 기본 팔레트 변경은 v2 이식본의 화면을 바꾸지 않았다(10장 1픽셀만, 원본끼리도 나는 차이).
- 페이지·콘솔 오류: 원본 0, 이식본 0. 타이머(T): 원본·이식본 모두 `01 회사 0:01 / 4:00` 형태로 같다. 화면 밖 요소·잘린 글자·깨진 이미지: 모두 0.
- 자동 상호작용(전체 보기, 탭 2, 장 2)도 원본과 이식본을 비교했다: 12장 중 11장 같음, 1장은 영상 재생 시간 글자 16픽셀.
- 15장 촬영과 상호작용 6장에 약 50초, 검사 전체(`check_deck.py`, 상호작용 12장 포함)에 약 1분 7초 걸렸다(macOS, Chrome, playwright-core 1.65.1).

## 하지 않은 것

- 사람이 이식본을 직접 넘겨 보며 원본과 같은 느낌인지 확인하지 않았다(스크린샷 비교만).
- 영상 재생 중의 프레임 연속성과 소리는 비교하지 않았다.
- 두 번째 사례(메이킹 강의 덱)는 아직 다시 만들지 않았다. DESIGN의 "확인하지 못한 것"에 닫을 조건이 있다.
