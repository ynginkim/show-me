# 청중과 시간 계획

Read ../resolve-show-me-tools/SKILL.md

입력은 요청, 브리프 답, 자료 위치, (있으면) Lightplay 영상의 장면 메모와 기존 `talk.md`다. 결과는 프로젝트의 `talk.md`(형식: `references/talk-template.md`)와 결정 기록이다. 다음 단계와 반복은 이 skill을 부른 playbook이 정한다. 직접 불러도 원자료를 바꾸지 않는다.

Read `../principle-audience-words/SKILL.md`, Read `../principle-show-the-real-thing/SKILL.md`. **principle-audience-words**, **principle-show-the-real-thing**을 적용한다.

## 절차

1. **브리프 표.** 청중(누구, 사전 지식, 인원), 목표(듣고 나서 청중이 할 수 있는 것 한 문장), 강조할 것과 뺄 것, 길이와 질문 시간, 장소·화면, 꼭 넣을 것, 자료 위치, 공개 범위를 채운다. 요청·파일에 없는 사용자 고유 사실만 묻는다. 청중·목표·강조와 뺄 것·공개 범위는 사용자의 의도이고, 나머지 단계(구간, 장 목록, 실물 고르기)는 이 skill이 정하는 계획이다. 계획은 승인받지 않는다(mode의 "브리프").
2. **한 문장.** 청중이 강의 뒤에 기억할 한 문장을 정한다. 장마다 이 문장에 무엇을 더하는지 설명할 수 없는 장은 뺀다.
3. **구간 예산.** 강의 길이에서 질문·전환 여유를 빼고 구간 2~4개로 나눈다. 구간 예산 합은 강의 길이를 넘지 않는다. 표지·마무리는 구간 밖으로 둔다. 시연(실제 앱 열기, 영상 재생)이 있는 구간은 시연 시간을 예산 안에 따로 적는다.
4. **장 목록.** 장마다 구간, 제목, 한 문장, 보여 줄 실물(녹화·캡처·링크·도식), 예상 초를 쓴다. 비전공 청중에게는 한 장 60~120초, 한 장에 메시지 하나를 기본으로 하고, 장 수를 줄여 여유를 둔다. 예상 초 합이 구간 예산을 넘으면 장을 합치거나 뺀다. 글자를 줄이거나 말을 빨리 해서 맞추지 않는다.
5. **실물 고르기.** **principle-show-the-real-thing**: 과정이 화면에 남는 일은 녹화·캡처·실제 링크로, 화면에 보이지 않는 과정(밤사이 여러 작업, 하루의 순환)만 도식으로 정한다. 공개 범위가 걸린 실물은 "현장 전용"으로 표시한다.
6. **말 고르기.** **principle-audience-words**: 제목·라벨에 내부 이름(브랜치, PR 번호, 도구 옵션)을 쓰지 않는다. 원문을 보여 줘야 하면 "원문 보기"처럼 접어 둘 곳을 장 목록에 적는다.
7. **Lightplay 영상이 있을 때.** 영상이 이미 말한 메시지와 장면을 적고, 덱은 그것을 되풀이하지 않고 자세히 보여 줄 것(녹화 원본, 실제 문서, 질문)을 맡게 한다. 영상을 트는 자리(보통 표지 다음)를 장 목록에 넣는다. 영상의 시각 언어(색, 시간대 표현)를 덱에서 이어 쓸지 정하고 이유를 적는다.
8. **결정 기록.** 적용한 principle과 바뀐 결정을 `talk.md` 끝에 남긴다.

## 수정할 때

시간을 줄이거나 순서를 바꾸면 구간 예산과 장 목록을 먼저 고친 뒤 build-deck에 넘긴다. 장 번호가 바뀌면 `data-goto`와 장면 대상(`ShowMe.scene(<번호>)`)도 바뀐다는 것을 결과에 적는다.

## 돌려주는 것

`talk.md` 경로, 구간 예산 합과 예상 초 합, 현장 전용 실물 목록, 사용자에게 확인이 필요한 사실(있으면).

이 기준의 장당 시간과 "한 장에 메시지 하나"는 2026-11-25 강의(비전공 교수 대상 20분)에서 왔다. 두 번째 사례 확인 전(잠정).
